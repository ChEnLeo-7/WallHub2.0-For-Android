# SteamKit2 long-lived account-session behavior

**Scope.** Official SteamRE/SteamKit sources and first-party source comments only. Links are pinned to upstream commit [`24131c045655ddaa1e0e60880b2b1af28f69e89c`](https://github.com/SteamRE/SteamKit/commit/24131c045655ddaa1e0e60880b2b1af28f69e89c) so the cited lines remain stable.

## Practical state model

Keep **remembered identity**, **CM transport**, and **authenticated session** as separate states:

1. **Remembered/restorable identity**: the application has securely retained an account name plus refresh token (and, when supplied, per-account Guard data). This says only that another login can be attempted. `AuthPollResult` explicitly identifies `AccountName`, a `RefreshToken` suitable for `SteamUser.LogOnDetails.AccessToken`, a subordinate `AccessToken`, and optional per-account `NewGuardData` ([`AuthPollResult`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Authentication/AuthPollResult.cs#L10-L40)).
2. **Connected transport**: `SteamClient.ConnectedCallback` means the client is securely connected to a CM; it does **not** mean an account has logged on. `SteamClient` posts it from `OnClientConnected`, whereas account login is a later `SteamUser.LogOn`/`LoggedOnCallback` exchange ([`SteamClient.OnClientConnected`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/SteamClient/SteamClient.cs#L348-L358), [`SteamUser.LogOn`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Handlers/SteamUser/SteamUser.cs#L217-L238)).
3. **Usable authenticated session**: only after `SteamUser.LoggedOnCallback.Result == EResult.OK`, and only until a `LoggedOffCallback` or `DisconnectedCallback` invalidates that live generation. SteamKit exposes `IsConnected` as physical CM connectivity and `SessionID`/`SteamID` as values assigned after successful logon; these are distinct signals ([`CMClient` live fields](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/CMClient.cs#L79-L109)).

**Consumer rule:** do not label a persisted account as “logged in,” and do not equate `IsConnected` with authorization. Track a successful `LoggedOnCallback` for the current connection generation and clear that state on either `LoggedOffCallback` or `DisconnectedCallback`. A retained refresh token can support recovery, but it is not proof that a currently usable Steam session exists.

## Connect/disconnect and callback pumping

- `CMClient.Connect` asynchronously chooses a CM, establishes the encrypted channel, and reports either `SteamClient.ConnectedCallback` or `SteamClient.DisconnectedCallback`. Its own contract is explicit that **SteamKit does not reconnect automatically**; the consumer must handle disconnection and call `Connect` again, “preferably after a short delay” ([`CMClient.Connect`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/CMClient.cs#L157-L170)).
- `DisconnectedCallback` means the physical CM connection ended. Its `UserInitiated` flag distinguishes an intentional disconnect from network/server failure ([`SteamClient.DisconnectedCallback`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/SteamClient/Callbacks.cs#L23-L38)). On disconnect, SteamKit clears `SessionID` and `SteamID`, stops the heartbeat, posts `DisconnectedCallback`, cancels pending jobs, disables job timeouts, and clears handler caches ([`CMClient.Disconnected`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/CMClient.cs#L460-L490), [`SteamClient.OnClientDisconnected`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/SteamClient/SteamClient.cs#L359-L374)).
- Callbacks are queued by `SteamClient`; `CallbackManager` dispatches them to subscriptions. `RunCallbacks` handles one queued item without waiting, `RunWaitCallbacks(timeout)` waits for and handles one, `RunWaitAllCallbacks(timeout)` drains the queue after the first item, and `RunWaitCallbackAsync` is the asynchronous/cancellable form ([`CallbackManager`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/SteamClient/CallbackMgr/CallbackMgr.cs#L44-L115)). The official authentication sample maintains a callback loop and states that callbacks must be handled by the manager to be routed ([authentication sample](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/Samples/000_Authentication/Program.cs#L17-L45)).

Therefore a long-lived owner needs a continuously running callback pump for as long as the client is active. Stopping it prevents subscribed state transitions from being observed even though network work and callback enqueueing may continue.

## Refresh-token login and remembered credentials

`SteamUser.LogOnDetails.AccessToken` is unfortunately named broadly. The first-party authentication result says its **refresh token** may be supplied to this property, and the official sample does exactly that:

```csharp
steamUser.LogOn(new SteamUser.LogOnDetails {
    Username = pollResponse.AccountName,
    AccessToken = pollResponse.RefreshToken,
    ShouldRememberPassword = shouldRememberPassword,
});
```

Sources: [`AuthPollResult.RefreshToken`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Authentication/AuthPollResult.cs#L15-L30), [official authentication sample](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/Samples/000_Authentication/Program.cs#L71-L93). `SteamUser.LogOn` requires a username plus password or this token, posts `LoggedOnCallback(EResult.NoConnection)` if the CM is not connected, and sends the token in the CM logon message ([`SteamUser.LogOn` implementation](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Handlers/SteamUser/SteamUser.cs#L225-L304)).

For persistence, `AuthSessionDetails.IsPersistentSession` and `LogOnDetails.ShouldRememberPassword` must be used together; both the property comment and sample say to set the latter when the former is true ([`LogOnDetails.ShouldRememberPassword`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Handlers/SteamUser/SteamUser.cs#L78-L88), [`AuthSessionDetails.IsPersistentSession`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Authentication/AuthSessionDetails.cs#L45-L62)). Optional `NewGuardData` should be stored per account and has its own expiration ([`AuthPollResult.NewGuardData`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Authentication/AuthPollResult.cs#L28-L32), [sample comment](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/Samples/000_Authentication/Program.cs#L71-L80)).

Do not confuse the two token roles: the official WebCookie sample says the subordinate access token can be used as `steamLoginSecure`, while the refresh token is required to generate new access tokens; it also demonstrates replacing a refresh token if renewal returns one ([WebCookie sample](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/Samples/002_WebCookie/Program.cs#L65-L76), [renewal](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/Samples/002_WebCookie/Program.cs#L98-L115)).

## `LoggedOn`, `LoggedOff`, and `Disconnected`

- **`LoggedOnCallback`** is the result of a logon attempt, not merely a connection event. Check both `Result` and, for diagnostics, `ExtendedResult`; only `EResult.OK` establishes the authenticated edge ([callback definition](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Handlers/SteamUser/Callbacks.cs#L20-L44), [sample result check](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/Samples/000_Authentication/Program.cs#L103-L118)).
- **`LoggedOffCallback`** means the server told the client it was logged off; it carries an `EResult` ([definition](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Handlers/SteamUser/Callbacks.cs#L189-L213)). CM handling clears `SessionID`, `SteamID`, `CellID`, public/country data and stops heartbeat. `TryAnotherCM` and `ServiceUnavailable` additionally mark the current endpoint bad ([`CMClient.HandleLoggedOff`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/CMClient.cs#L609-L633)). A logged-off client is therefore not authenticated even if its physical socket has not yet produced `DisconnectedCallback`.
- **`DisconnectedCallback`** is transport loss. It invalidates the live account session whether or not a preceding `LoggedOffCallback` was observed. `SteamUser.LogOff()` asks the server to log off and documents that the server will disconnect afterward ([`SteamUser.LogOff`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Handlers/SteamUser/SteamUser.cs#L349-L359)).

A useful implementation state machine is thus `REMEMBERED` → `CONNECTING` → `CONNECTED_UNAUTHENTICATED` → `AUTHENTICATED`, with either callback moving the current live generation out of `AUTHENTICATED`; a stored credential remains `REMEMBERED` until explicitly removed or rejected as unusable.

## Heartbeats, reconnect, backoff, and CM rotation

- After a successful CM logon, `CMClient` reads the server-provided `legacy_out_of_game_heartbeat_seconds`, starts an internal `ScheduledFunction`, and sends `CMsgClientHeartBeat`; it stops this timer on logoff or disconnect ([heartbeat setup and successful-logon handling](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/CMClient.cs#L151-L155), [`HandleLogOnResponse`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/CMClient.cs#L571-L607)). `ScheduledFunction` uses a `System.Threading.Timer`, so heartbeat transmission is internal and independent of `CallbackManager` pumping ([`ScheduledFunction`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Util/ScheduledFunction.cs#L13-L60)). The pump is still required to observe disconnect/logoff and other callbacks.
- SteamKit provides **no automatic reconnect loop and no prescribed exponential-backoff formula**. Its only general contract is reconnect after a short delay. The legacy Steam Guard sample uses a fixed five-second delay for that specific reauthentication path ([sample](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/Samples/005_LegacySteamGuard/Program.cs#L104-L114)); this is an example, not a library-wide retry policy. A consumer should therefore own cancellation, retry limits/jitter/backoff, and avoid retrying intentional shutdowns.
- With no explicit `ServerRecord`, `Connect` asks `SmartCMServerList.GetNextServerCandidateAsync`. Successful connections mark the endpoint good; unexpected disconnects mark its host bad ([candidate selection](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/CMClient.cs#L170-L219), [quality updates](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/CMClient.cs#L440-L474)). The smart list prefers entries without a recent bad timestamp, preserves bad state for five minutes by default, then makes old failures eligible again ([`BadConnectionMemoryTimeSpan` and selection](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Discovery/SmartCMServerList.cs#L202-L229), [`GetNextServerCandidateInternal`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Discovery/SmartCMServerList.cs#L341-L398)). Thus repeated consumer `Connect()` calls naturally rotate away from recently failed CM hosts; consumers should not pin the failed endpoint unless they intentionally override this behavior.
- The CM list is refreshed from Steam Directory when stale, otherwise from the configured provider, with official fallback endpoints only as a last effort. The default list freshness is seven days; `FileStorageServerListProvider` is available if endpoint discovery should persist across process restarts ([resolution chain](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Discovery/SmartCMServerList.cs#L122-L205), [`FileStorageServerListProvider`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Discovery/FileStorageServerListProvider.cs#L10-L84)).
- Steam Directory requests use `SteamConfiguration.CellID`; user and anonymous logon messages use `LogOnDetails.CellID ?? Configuration.CellID`. A successful logon exposes the server-recommended `CMClient.CellID`; a logged-off event clears it ([Directory request](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/WebAPI/SteamDirectory.cs#L43-L60), [logon Cell ID](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/Handlers/SteamUser/SteamUser.cs#L263-L274), [recommended Cell ID lifecycle](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/CMClient.cs#L92-L103)). The implementation does not copy that recommendation back into immutable `SteamConfiguration`; a consumer that wants it used by a later client/configuration must deliberately carry it forward via `WithCellID` or the next `LogOnDetails.CellID` ([`WithCellID`](https://github.com/SteamRE/SteamKit/blob/24131c045655ddaa1e0e60880b2b1af28f69e89c/SteamKit2/SteamKit2/Steam/SteamClient/Configuration/SteamConfigurationBuilder.cs#L50-L57)).

## Integration checklist

- Persist account identity/refresh token/Guard data securely, but publish it as **saved/restorable**, not connected or logged in.
- Run one callback pump for the lifetime of the active `SteamClient`.
- On each `ConnectedCallback`, issue one `SteamUser.LogOn` for the intended current generation.
- Publish authenticated readiness only after `LoggedOnCallback.Result == OK`.
- Revoke readiness immediately on `LoggedOffCallback` or `DisconnectedCallback`; fail or fence in-flight account work tied to that generation.
- Reconnect only for non-intentional loss and under an application-owned delayed/backoff policy; call parameterless `Connect()` to benefit from SteamKit’s CM quality rotation.
- Let SteamKit own heartbeat timing; do not substitute callback pumping for heartbeat maintenance.
- Treat Cell ID as routing advice, not authentication proof, and deliberately decide whether to carry the server-recommended value into future configuration.
